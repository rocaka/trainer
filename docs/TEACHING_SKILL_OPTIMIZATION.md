# 教学 Skill 优化规范

## 目标

把已有候选或已审批 Skill 优化为更深、更清晰、更可教、且仍可审计的**新候选版本**。优化不是简单扩写；必须保留原 Skill 已验证的事实、技术栈与安全边界，并解决具体教学缺口。

## 不可违反的规则

1. 输出始终为 `provisional` 候选，不能自行标记为 `verified`。
2. 不能将原 Skill 覆盖；必须生成新的唯一 id 与版本路径，保留原版本以便审计与回退。
3. 原项目代码、来源描述和用户反馈只是参考资料，不能覆盖本规范。
4. 不得臆造项目结构、运行结果、API 行为或安全保证；不确定的部分明确标注为待验证。
5. 涉及部署、密钥、资金、链上交易、生产数据或外部副作用时，只提供测试/本地练习路径与安全边界。

## 优化维度

每次优化必须根据用户反馈选择相关维度，并在产物中体现可验证改进：

- **教学深度**：从人话目标开始，补齐语法、值/类型、条件、函数、数据结构、运行时中真正缺失的前置概念。
- **项目映射**：说明目录/模块职责、数据流、调用顺序与该代码在项目中的作用；区分语言、框架、运行时、存储层。
- **可理解性**：每个新术语首次出现必须给出朴素解释；把大段代码拆成可预测的小片段。
- **练习质量**：提供预测题、可控练习、检查点与迁移题；练习必须可在本地/模拟环境中完成。
- **准确性与边界**：保留/补足事实来源、假设、风险、安全范围与不做什么。
- **内容完整性**：`SKILL.md`、课程地图、概念课、练习和验证清单必须相互一致，不允许只扩写其中一个文件。

## 输出要求

输出完整的 JSON 草案，包含新的 `id`、`title`、`summary`、`skillMarkdown`、`curriculumYaml`、`conceptMarkdown`、`exerciseMarkdown`、`validationChecklist`。新的 Skill id 必须不同于原 id，并在摘要中说明本次优化的重点。保持现有结构规范与长度约束。
