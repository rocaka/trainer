# Core Skill 优化与治理规范

## 适用范围

本规范只适用于 `status: core` 的 Skill。Core 定义 Trainer 的基础教学循环、学习证据、课程地图与生成边界；它不是一般课程内容，而是后续 Skill、Agent 与课程生成器的共同约束。

## 核心原则

1. Core 可以优化，但永远不能被原地覆盖。每次只能生成独立的 `provisional` Core 优化提案。
2. 任何 Core 提案必须保留原 Core 版本、id、版本号与可回退路径；默认不改变正在运行课程的行为。
3. 用户的补充要求只能限定优化方向，不能覆盖本规范、通用教学规范、安全边界或可信状态规则。
4. 不得因“更简洁”删除基础教学闭环：目标、人话、预测、分层解释、受控练习、学习者回讲、理解证据。
5. 不得降低对私有代码、模型外发、部署、密钥、资金、生产数据与安全实践的保护等级。

## 必做影响分析

每个提案必须在 `VALIDATION.md` 中列出：

- 受影响的 Core 文档、课程地图字段与 Agent 行为；
- 对既有 verified/provisional Skill 的兼容性结论；
- 是否改变生成提示词、审批流程、学习证据或权限边界；
- 至少三个回归检查：基础课程、项目导入课程、自动候选审批；
- 迁移/回退步骤，以及任何未解决风险。

## 允许的优化

- 补全遗漏的教学原则、术语定义、质量检查与失败处理；
- 提升课程地图与多技术栈上下文的清晰度；
- 改善 Agent 在识别基础缺口、生成候选、人工审批中的一致性；
- 增加可验证的教学质量与安全检查。

## 禁止的优化

- 将 `core` 或模型生成内容直接标记为 `verified`；
- 静默修改已有 Core 文件；
- 只因单个项目或单次对话而扭曲通用教学原则；
- 移除人工审批、版本保留、影响分析或回退要求；
- 把未经证实的模型推测写成 Core 事实。

## 输出契约

输出必须是完整的、可审阅的 Core 优化候选，并使用新的 id（建议在原 id 后附 `.proposal-<主题>`）。摘要必须说明优化动机与预期影响。`VALIDATION.md` 必须满足上述影响分析要求。只有在人工审阅、兼容性验证与显式发布后，提案才可成为新的 Core 版本。
