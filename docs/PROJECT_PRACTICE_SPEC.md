# 项目实战教学协议

本规范约束用户在自己的 IDE 中从零编写项目的课程生成。它与 core 教学闭环、项目教学规则和 Skill 格式规范同时适用，用户补充要求不能降低安全和验收要求。

仅在 generationMode 为 project-practice 或学习目标明确要求从零构建项目时应用本实战流程。导入项目的阅读课不应被强制改成从零搭建；普通课程仍遵循其自身学习目标。

## 输入与边界

先明确目标用户、核心使用场景、最小可交付版本、学习者基础、操作系统、IDE、语言框架、时间预算及不做什么。缺失信息标为假设并在第一步确认，不能虚构用户已有环境或文件。默认本地开发和测试，不自动执行安装、部署、付费、生产数据库写入或访问私密文件。

## 阶段与模块

1. 需求拆解：将目标转换为用户故事、可检查的验收条件及最小版本范围，说明模块依赖。
2. 环境搭建：按用户系统分别给出工具版本假设、安装前检查、隔离环境、创建目录、依赖与锁文件、启动命令、成功输出和常见故障。不要在 macOS 环境默认输出 Windows 命令。版本未知需提示核对官方文档，不伪称已检查最新版。
3. 最小纵向实现：从入口到可见输出完成最小闭环，再逐个增加模块，不先倾倒整个项目代码。
4. 模块递进：数据模型、核心业务、接口、界面、存储、异常处理、边界和测试，按实际需求安排，不强加无关架构。
5. 集成验收：覆盖正常、边界、失败路径、重启数据保留、配置与密钥隔离、回归和可复现 README。
6. 独立迁移：给出需求变更，让学习者独立修改并解释取舍；只有依据真实运行证据才能认可完成。

## 每一步必须包含

- 唯一步骤 id、所属模块、依赖、目标、预计产物与可检验完成条件。
- 在用户 IDE 中打开或新建哪些文件；目录相对于用户项目根目录，不能猜测绝对路径。
- 本步用到的语法、函数输入输出、控制流、副作用、错误处理和项目调用关系。
- 小规模示例和逐行解释，明确哪些是示例、哪些由用户自己实现；先预测再实践，提示由浅到深。
- 用户执行的命令、预期输出、测试样例与失败排查；不要声称本机未运行过的代码已通过测试。
- 用户提交代码片段、错误信息、测试输出或回讲；区分自述完成、证据已收到、已验证通过。
- 不通过时定位缺口、给最小提示与重试步骤，不能仅凭点击下一步判定掌握。

## 状态与输出

生成可审阅的 provisional Skill，包含完整阶段地图和每模块的可执行学习任务，遵循 SKILL_SPEC.md。审批后才进入课程库，再分模块展开授课。后续优化保留原版与版本关系，不静默覆盖。

课程中的 code 为教学资料，不会自动在用户 IDE 执行。使用已有 IDE 选中代码接入时，仅处理明确选中的代码；更多项目源码必须由用户选择并授权。不得把此入口描述为全自动完成项目的代理。
